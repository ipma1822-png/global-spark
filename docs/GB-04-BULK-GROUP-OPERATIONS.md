# GLOBAL SPARK · GB-04 대량운영·단체활동·일괄승인

Version: GB-04 · v3.20.0

## 목적

성장기지에서 100명 이상을 운영할 때 지도자가 수백 건을 반복 입력·승인하는 구조를 피한다.

운영 원칙은 다음과 같다.

- 아이·부모 일반 기록: 제출 → 성장기지 확인 → 공식 SPARK 확정
- 지도자가 현장에서 확인한 단체활동: 참여자 선택 → 한 번에 공식 SPARK 등록
- 승인대기 기록: 여러 건 선택 → 한 번에 승인 또는 거절
- 기존 개별 등록·개별 승인 기능은 그대로 유지한다.

## 1. 단체활동 SPARK

기존 `spark_center_bulk_register_activity` 인터페이스를 유지하여 기존 화면과 호환한다.

최대 100명의 참여자를 한 번에 선택할 수 있다.

GB-04부터 각 실행은 `spark_group_activity_batches`에 하나의 단체활동 묶음으로 기록된다.

각 아이의 실제 `spark_activities`와 `spark_ledger` 기록은 기존과 동일하게 개별 생성되며, 동일한 batch UUID가 `source_event_id`에 연결된다.

따라서 개인 성장기록은 유지하면서도 본부·성장기지에서는 하나의 수업·행사·캠페인 단체활동으로 추적할 수 있다.

## 2. 일괄 승인

신규 RPC:

`spark_center_bulk_review_submissions(p_center_code, p_submission_ids, p_action, p_review_note)`

- 최대 100건
- `approved` / `rejected`
- 해당 성장기지 STAFF 권한 확인
- 선택한 모든 항목이 해당 성장기지의 `pending` 기록인지 선검증
- 하나라도 잘못된 항목이면 전체 작업 중단
- 승인 시 기존 `spark_center_review_submission` 로직을 재사용
- 승인된 건만 `spark_activities` + `spark_ledger` 생성

## 3. 승인센터 UI

`center-approvals.html` → GB-04 · v3.20.0

추가 기능:

- 아이+부모 / 아이만 / 부모만 필터
- 보이는 기록 전체 선택
- 개별 체크박스
- 선택 해제
- 선택 건수 표시
- 일괄 확인 메모
- 선택 일괄 승인
- 선택 일괄 거절
- 최대 100건 보호

기존 개별 승인·거절은 그대로 유지한다.

## 4. 안전 원칙

- 익명 사용자는 단체등록 및 승인 RPC 실행 불가
- 로그인 후에도 해당 성장기지 STAFF 권한 확인
- 단체 대상은 현재 해당 성장기지의 활성 회원만 허용
- 일괄 승인은 현재 해당 성장기지의 `pending` 제출만 허용
- 기존 `spark_members.center_id`, 기존 활동·원장 구조는 변경하지 않음
- 기존 개인기록·캠페인·MISSION·성장분석 기능은 변경하지 않음

## 5. 운영 효과

기존 현실 문제:

100명 × 3개 행동 = 하루 300회의 지도자 입력/승인 가능성

GB-04 이후:

- 수업 전체가 함께 한 행동 → 한 번의 단체활동 처리
- 아이·부모가 개별 제출한 기록 → 여러 건을 묶어 일괄 확인
- 개별 확인이 필요한 건만 따로 검토

따라서 성장기지는 데이터 입력소가 아니라 교육·확인·인정의 운영기지로 작동한다.
